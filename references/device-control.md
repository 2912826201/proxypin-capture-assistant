# 默认由 agent 接管设备

先检查并使用真实的手机控制能力，再决定是否需要用户动手。ProxyPin MCP 管理抓包与规则，不提供通用手机 UI 控制；不要把 MCP 连通当作手机已可控制。

## 发现能力

优先使用当前环境中可用、适用且允许的设备控制 MCP。读取工具文档和设备列表，确认目标设备，再读取当前屏幕。若 Android 无专用工具，探测 `adb` 与已连接设备；当前电脑 SDK 路径不能写死。iOS 只有实际可用的设备/模拟器控制能力才可接管，不能假定 ADB 支持 iPhone。浏览器任务使用可用浏览器控制。

Android ADB：

```text
adb devices -l
adb -s <本次核实的序列号> shell dumpsys window
adb -s <本次核实的序列号> shell uiautomator dump /sdcard/proxypin-capture-ui.xml
adb -s <本次核实的序列号> shell cat /sdcard/proxypin-capture-ui.xml
```

这些命令供 agent 执行，不让用户复制。多设备时按用户指定目标选定；不能确定时只补问设备选择。状态为 `device` 直接开始；`unauthorized` 时无法靠未授权 ADB 点自己的授权弹窗，才提醒用户解锁并允许 USB 调试。`offline` 时先查连接/服务，可恢复就代劳；物理断开且无其他控制路径时才请用户接线。没有 ADB 但手机 MCP 可读流量时，可以继续连接分析，UI 操作能力仍需单独判断。

新建 Android 自动化环境按 [隔离模拟器路线](emulator.md) 检查兼容性并准备。模拟器先用 `adb -s <serial> emu avd name` 与本次登记的 AVD 名称交叉验证，再操作；用户真机与已有 AVD 不因同时在线而成为默认目标。所有安装、UI、转发和 root/remount 命令显式指定已核实 serial；系统 CA 操作只用于本任务新建且具备相应能力的隔离 AVD。

## 操作与验证循环

1. 读取真实 UI 层级或截图，确定当前页面与控件。ADB 可导出截图到本次工作目录，用可用图像查看工具检查；注意 shell 的二进制输出处理，不能将截图通过不兼容的文本重定向损坏。
2. 从控件文本、resource-id、可点击状态与实际 bounds 定位，执行普通点击、滑动、文本输入或返回。ADB 可用 `shell input tap/swipe/text/keyevent`。坐标必须来自当前屏幕，不复用上一设备或旧页面的坐标。
3. 操作后再次读 UI/截图，确认页面变化，再操作下一步。界面暂未加载时短暂等待并重读；持续卡住时报告具体状态，不无限点击。启动包名从已安装应用/manifest 或实际前台进程核实，不硬编码实例 App。
4. 抓包前记录 flow 基线；由 agent 进入用户目标页面、刷新、搜索或打开详情，再检查新流量。批量页面浏览按已证实 UI/分页执行，避免误触购买、支付或更改账号。接口重放仍需确认只读。

在用户已授权抓包范围内，由 agent 完成 ProxyPin 普通设置、开始抓包、可操作的 VPN/证书确认、目标 App 浏览与结束恢复。系统密码、生物识别、无法从锁屏继续的操作交给用户；不能尝试猜密码。控制工具拒绝某操作时遵守限制，清楚说明哪个动作需要用户。

## 用户介入的条件

仅在以下情况及时提出当前具体动作：

- 未授权连接需要用户在设备确认，或需要物理接线/解锁。
- 密码、生物识别等本人输入，或系统/工具确实不允许代办的授权。
- 该设备/界面无可用控制工具，或在查看当前状态并尝试适当操作后仍无法完成。
- 当前操作将超出用户抓包目标，例如必须进行购买才能进入数据范围；不能擅自执行。

不要因为“手机步骤通常是手动”就交给用户。也不要为了证明尝试而反复运行已明确不可用的工具。提示时解释当前限制，只给完成后可恢复自动操作的最小步骤；独立验证成功后立即接回控制。

恢复同样由 agent 先做。手机控制不可用的剩余恢复动作再提示用户，并说明是否验证；不能把整份恢复清单交给有工具可控的手机用户。

ADB 行为依据：[Android 官方文档](https://developer.android.com/tools/adb)。跨电脑使用时重新发现工具与设备，不依赖原会话连接状态。
