# 主动指导必要的手动操作

用户不会代码。先按 [设备接管](device-control.md) 检查并使用工具；agent 能做的操作全部代劳。下面是**无法代劳时**的提醒，不是默认发给用户的待办清单。每轮只给当前必要的 1–3 步，不把配置代码、JSON、ADB 命令交给用户执行。设备解锁凭据、密码、生物识别、无法自举的授权，以及没有访问工具的手机操作才由用户完成。

## 提醒格式

用自然语言给“现在需要你做什么 → 从哪进入 → 点什么 → 看到什么算完成 → 我接下来怎样验证”。需要原因时一句话解释。UI 未核实时不要假装知道坐标或按钮；给设置搜索词或请用户描述当前文字，再按实际界面继续。

例：“当前工具不能操作这个手机的 VPN 确认界面。请在系统弹窗中点允许；若要求密码，由你输入。完成后我会检查新请求，并继续自动操作。”能从工具点击的普通 VPN 确认不发此提醒。

用户回复完成后独立验证。没有工具能查看的状态如实标为用户报告，不能据此声称完全验证。用户未回复时步骤仍待完成；不要把超时当完成或反复发送同一提醒。继续能独立做的工作，恢复对话时说明当前卡在哪一步。

## 按路径选提醒

| 需要的动作 | 给用户的操作入口与成功标志 | agent 验证 |
|---|---|---|
| 启用 MCP，UI 无法代办时 | 电脑 ProxyPin 顶部 AI 图标 → MCP 服务；手机 ProxyPin 设置 → MCP 服务。开启后显示“运行中”。读取面板当前地址 | MCP 初始化、工具列表与状态读取成功；核对连接的实例 |
| 手机 LAN MCP | 手机与电脑连接同一 Wi-Fi，手机保持 MCP 运行；令牌通过本地隐藏输入/安全配置接收 | 实际连通，不用同名 Wi-Fi 代替可达性；不要求 token 发到聊天 |
| Android USB 调试，仅 ADB 路径 | 连接并解锁手机；设置搜索“USB 调试”。出现“允许 USB 调试”时允许 | `adb devices -l` 目标设备为 `device`。已有 `device` 不重复要求；`unauthorized` 只指导授权弹窗 |
| 手机 VPN 抓包，无法代办时 | ProxyPin 主页开始抓包；系统询问 VPN 连接/添加配置时允许，密码由用户输入。普通点击能控制时由 agent 做 | 可访问时读设备 VPN 状态，再看本次目标新流量；`recording=true` 不替代 VPN 验证 |
| VPN 冲突 | 仅发现冲突时说明设备通常只能运行一个 VPN，请用户暂时停止冲突 VPN，并记住原状态 | 重试目标流量，完成后提醒恢复原 VPN；不静默关闭用户工具 |
| 手机经电脑代理 | 同网；给当前电脑局域网 IP 与代理端口。iOS：设置 → Wi-Fi → 当前网络 ⓘ → 配置代理 → 手动；Android 根据机型在当前网络编辑/高级选项中设置代理 | 检查电脑监听和手机新流量。手机不能填写电脑的 `127.0.0.1`；若采用扫码连接按当前 ProxyPin UI 指导 |
| 必要的 HTTPS 证书，无法代办时 | 先准备并核对当前 ProxyPin CA；需要本人密码或不可操作的确认时才提示，能控制的安装/信任设置由 agent 做 | 有 `get_certificate_status` 时先读；再以目标新 HTTPS 正文验证，不能只凭“证书安装成功” |
| Android 用户 CA | 按当前机型设置搜索“安装证书/CA 证书”，选择本次 ProxyPin 的证书 | 确认实际证书，再检查目标 App 是否接受。某些 App 不信任用户 CA，不重复安装相同证书 |
| iOS 描述文件，第一轮 | 安装当前 ProxyPin 证书描述文件：设置 → 已下载描述文件 → 安装；若入口不同按当前 iOS 界面继续 | 无手机设置访问时仅记用户报告，后续仍检查真实 HTTPS |
| iOS 完全信任，第二轮 | 设置 → 通用 → 关于本机 → 证书信任设置，开启本次根证书的完全信任 | 电脑证书状态不能证明 iPhone 信任；以 iPhone 新产生的 HTTPS 正文验证 |
| Windows/macOS/Linux 证书，无法代办时 | Windows 指向“受信任的根证书颁发机构”；macOS 使用当前证书的钥匙串信任设置；Linux 按发行版与浏览器证书库核实入口 | 优先由 agent 执行可用配置；只有本人密码或不可操作的 UI 才交给用户，不编造统一 Linux 路径 |
| 触发目标操作，手机/浏览器控制不可用时 | 提供用户指定页面的具体动作，例如“打开列表、刷新一次、点开一件商品；看到详情后告诉我” | 操作前记录时间/流量基线，检查新请求及正文；工具可用时由 agent 触发，不发手动提醒 |
| 导出 HAR 备用路径 | 当前 MCP 不可用时，指导用户在 ProxyPin 选择相关会话并导出 HAR 到可访问位置 | 读取真实 HAR；说明后续分析来源是导出文件，不能宣称 MCP 连接成功 |
| 完成后恢复 | agent 先恢复自己可控制的设置；主动提醒手机停止本次抓包 VPN、恢复本次 Wi-Fi 代理原值，再刷新页面验证联网 | 只恢复本次改动；无工具或未收到确认时列出尚未验证的项 |

## 触发前的最低门槛

MCP 连通后，只要路由可捕获即可先做样本验证。仅取 URL 时可能不需要解密全部 HTTPS。确实缺正文才推进证书步骤，不让用户为不需要的能力先做复杂设置。全程给具体操作，不给跨平台大清单。
