# 从真实样本生成采集脚本

这是默认执行路线。agent 负责分析少量真实请求、选择已验证方法、生成任务脚本并独立实测；运行脚本负责有界批量采集、检查点和指定文件夹保存。不要求 agent 在交付脚本前手动抓完整批量。用户只需要说明目标、范围与保存位置，必要时在原应用正常登录。

开始前按 [问题反馈流程](feedback-loop.md) 尝试同步已配置仓库的最新 Issues/评论并检查既有待提交队列。空白环境缺解释器时先走其中的最小能力分支，不阻塞主任务。先按当前症状、阶段和环境类别筛选经验，再用本机检查验证；经验中的“已解决”不能代替本次业务成功证据。无网络或读取权限时保留缓存状态并继续当前任务。

## 1. 确定目标并核实能力

**输入：** 用户目标、设备要求、输出位置与已有工具/捕获。

**执行：** 确认 App/网站身份、字段和范围；“全部”按可发现且可访问的目录有界采集，不能据此推断未知后端总量。实测命令在哪台机器运行、实际解释器、文件写入权限、设备/浏览器控制与 MCP 能力。输出文件夹用用户指定的真实绝对路径；尚未指定时先确定可写候选并继续不依赖位置的分析，不能把最终文件藏在 Skill 中。

将本任务的应用配置、原始正文和认证材料放在 Skill/仓库外的私有任务目录。通用 Skill 只保存方法和可复用代码，不加入本次应用的端点、签名密钥、账号或商品。

缺工具/设备、正常业务基线、MCP、抓包路由或正文时，进入 [准备与抓包规程](runbook.md) 的当前失败层；完成必需准备和真实样本后返回本流程。已有真实 HAR/捕获按其导入分支分析，不重复让用户配置手机。只有聊天且无工具/真实文件时明确当前缺少执行入口，不能生成“已实测”脚本。

**通过：** 目标与范围有记录；真实执行宿主可达目标，所需解释器/文件/采集能力有实际检查，输出路径已确定。

**失败：** 未确定目标只补必要信息；准备失败保留具体检查结果。不用工具名、文件存在或启动成功替代能力验证。

## 2. 分析少量样本并选路线

**输入：** 当前正常业务会话及一至数条完整真实 flow。

**执行：** 操作前记录 flow ID/时间基线，触发一个已知目标动作，再读新的请求、完整响应、HTTP 和实际业务状态。确认列表路径、名称/URL/真实 ID、分类/容器关系、分页参数、下一页/游标、结束依据，以及必要的认证/时间戳/nonce/签名输入。不把预览文本当完整正文。商品关系字段按 [输出约定](output-contract.md) 建立任务适配。

先取得一个非空样本并对照完整源对象抽查。随后触发第二页或下一游标，证明存在新增真实 ID；不是同一页换时间、旧 flow 或 agent 复制的 JSON。如果源数据确没有第二页/新增记录，只能报告已验证单页，不能通过可分页批量脚本验收。

### 路线选择

| 路线 | 选择条件 | 运行依赖 |
|---|---|---|
| 直接只读 API | 新鲜真实请求的两页重放均业务成功，第二页有新增 ID，分页及结束条件明确；必要的动态签名生成器已独立实测 | 当前合法会话或明确的正常登录/续期方式 |
| App/浏览器产生请求，MCP 收集 | App 可正常产生下一页请求，但动态签名算法未证明、重放失败或保留应用会话更可靠 | 正常登录的原 App/浏览器、实际控制工具、ProxyPin 与可达 MCP |
| 已有捕获提取 | 只有真实 HAR/已保存 flow，或用户只要求分析已有捕获 | 本地捕获文件；能力范围仅为已捕获数据 |

优先采用当前已被真实证据证明、依赖可持续满足的路线。只复制请求、固定 Cookie 或旧签名后成功一次，不能作为直接 API 路线依据。签名看似时间戳/MD5/Base64 也不能猜算法。已有捕获提取不能称作主动批量采集。

### 动态签名必须验证的内容

1. 从本次请求确认实际动态字段和签名输入；秘密保留在私有任务配置或运行时环境，不能固化在通用模板。
2. 用适配器生成新请求，第一业务页解析成功；在相同合法会话下用实际第二页参数生成新的签名请求，业务成功且新增 ID。保留方法、时间、参数的脱敏证据及输出计数。
3. 在新进程中再生成请求，排除依赖 agent 内存、旧签名或临时交互变量。若依赖 App/浏览器内部生成新签名，则选该路线，不能把它包装成独立算法已实现。

签名算法未证实时停止 API 猜测，保留原 App/浏览器产生新请求并由 MCP 捕获。该路线的采集脚本必须真正串起可用请求来源、采集和输出；如果仍需用户翻页，要明确提示当前动作和依赖，不能称为无人值守全自动脚本。

### 正常登录门槛

出现登录页面、目标业务 HTTP 401，或在真实响应中已确认的业务登录失效码，立即停止目标采集，保存本次运行的部分结果和检查点，并主动提醒用户先在原 App/网站正常登录。HTTP 403 同样先停止、主动通知用户检查原 App/网站的正常会话和当前页面；它可能是权限或签名问题，不能仅凭 403 断言凭据失效或自动输出 `LOGIN_REQUIRED`，按实际证据处理。不要把 HTTP 200 的认证失败正文当数据，不猜通用“成功码”。本人验证码、密码或生物识别只在用户本机输入。

`context.http_json()` 遇 HTTP 200 的 HTML/其他非 JSON 返回 `invalid_response_json`，不自动推断登录失效。只有从实际 App 页面或另外编写并实测的响应解析器证明是登录页，才提示正常登录；否则保留解析/响应错误并检查当前失败层，不猜认证状态。

用户完成后由 agent 验证正常目标页面和一条新业务成功响应，再更新私有会话并续跑。时间过去或用户未回复不算登录完成。ProxyPin MCP 的服务鉴权错误先核对当前实例和本地令牌；它与业务登录失效分别处理，不将 MCP 的 401/403误报为 App 账号问题。

**通过：** 至少一个真实非空样本及第二页新增 ID；字段、实际业务状态、分页与所选路线均有证据。直接 API 额外通过新签名两页重放及新进程检查。

**失败：** 没有完整正文回到所需抓包层；没有新增数据检查真实分页/缓存；认证失效先通知正常登录；签名未证明切换保留应用路线或如实交付当前边界。失败不生成假商品。

## 3. 生成运行文件并独立实测

**输入：** 经验证的路线、任务适配、真实样本、分页证据和输出路径。

**执行：** 为本任务生成 `collect_data.py` 和实际需要的运行模块/配置。商品任务使用下述工厂和运行包；工厂只做本地输入检查与打包，不安装工具、不取流量、不推导签名，也不替 agent 判断业务成功。先实际读取当前实现的 `--help`，再填入本次已验证值执行；不发给用户猜参数或改代码。生成脚本不得依赖 agent 会话中的未保存变量、Skill 的相对路径或复制好的样本输出。

### 商品运行包的确切接口

agent 在任务私有目录编写 `target_adapter.py`，导出 `run(context)`，逐页 `yield` 一个包含 `items` 和 `state` 的对象，可有 `stop_reason`。只有完成当前业务页验证后才 yield，再请求下一页；运行时能在页数上限处停止。每个商品关系必须提供真实 `name`、`url`、`source`，可提供真实 `id` 和 `request_id`；当前通用运行包不接受任意额外商品字段。`source` 的 API 主机必须来自观察到的 `allowed_hosts`。`state` 仅保存可恢复页/游标等非秘密值，不保存 Cookie、token、签名或原始正文。

直接 API 适配通过 `context.http_json(...)` 执行已验证的只读 JSON 请求；需要认证时用 `context.secret(...)` 从本地环境或交互终端隐藏输入取得。业务登录失效码和实际成功码由适配器按本次 JSON 响应检查；登录页面只能根据已读取的实际 App 页面或另行实测的响应解析器确认，`http_json()` 本身不识别 HTML 登录页。已确认失效时调用 `context.fail("login_required", "请先在原 App/网站正常登录，再继续采集。")`。HTTP 200 不自动通过业务验证。适配器是 agent 审查的 Python 代码，不是代码沙箱；只读范围、设备操作、签名生成和业务分页由适配器实际实现并实测。

已确认登录失效而仅调用 `context.fail("login_required")` 时，运行时也会给出默认的本机正常登录提醒，并保留本次部分结果和检查点；业务错误是否属于登录失效仍须按真实证据识别。

工厂配置仅含以下字段，应用专用值从本次观察建立，不复制到通用仓库：

| 字段 | 约束/来源 |
|---|---|
| `version` | 整数 `1` |
| `target` | 本次目标标签 |
| `strategy` | `direct_http` 或 `app_capture`，按第二阶段证据选择 |
| `allowed_hosts` | 已观察的 API 主机列表，不猜域名 |
| `max_pages` | 本次任务跨续跑的累计页数上限，整数 `1..1000` |
| `adapter_config` | 适配器需要的已观察非秘密元数据 |
| `allow_signed_image_urls` | 可选，默认 `false`；确认是图片资源签名才设 `true` |

工厂输入的证据报告字段固定为 `version:1`、相同 `target/strategy`、`source:live_capture` 或 `direct_replay`、`status:agent_verified`、非零整数 `sample_count`、带时区 ISO 时间 `observed_utc`，以及 `checks` 的 `full_body/business_success/mapping/readonly` 全为 `true`。`direct_http` 必须使用 `source:direct_replay`。只有真实观察后才写这些断言；报告没有第二页/新 ID/签名字段，须另外保存相关脱敏证据并由 agent 验收，不能为通过工厂检查而填写未经验证的值。工厂保存报告 hash 和观察时间，并不验证报告内容为真。

工厂命令为 `generate_collector.py --adapter --config --evidence-report --bundle-dir`，四项均为真实绝对路径；只有明确重建现有运行包才加 `--overwrite`。打包目录必须在 Skill/仓库之外，不能覆盖输入证据。生成 `collect_data.py`、`target_adapter.py`、`collector_config.json`、`proxypin_mcp.py` 和 `export_capture.py`，这五个文件共同构成运行包。

运行命令为 `collect_data.py --output-dir --max-pages`；两页实测加 `--probe 2`，单页诊断可用 `--probe 1`，但单页不算通过两页验收。续跑用 `--resume`；明确替换以前运行结果才用 `--overwrite`，两者互斥。默认使用新空输出目录，`--overwrite` 不备份或保留以前结果。App/MCP 适配实际需要时才传 `--device`、`--adb`、`--mcp-endpoint`，其值从当前设备及 MCP 面板发现。`--output-dir` 必须是用户选定的绝对目录，并与运行包目录不同。配置 `max_pages` 是任务累计上限；CLI `--max-pages` 是本次调用预算，续跑也只能采集累计上限内的剩余页数。

以下是 agent 执行方式。变量先从本次已验证路径/范围记录赋值并检查非空、文件存在；不把未赋值命令交给用户：

```powershell
& $pythonPath -I -X utf8 -B (Join-Path $skillRoot 'scripts/generate_collector.py') --adapter $adapterPath --config $configPath --evidence-report $evidencePath --bundle-dir $bundleDirectory
& $pythonPath -I -X utf8 -B (Join-Path $bundleDirectory 'collect_data.py') --output-dir $outputDirectory --max-pages $pageLimit --probe 2
```

`$pythonPath/$skillRoot` 来自实际解释器与 Skill 定位；`$adapterPath/$configPath/$evidencePath` 是本次创建并审查的私有输入；`$bundleDirectory/$outputDirectory` 是用户选定文件夹下分别用于运行包和数据的不同绝对目录；`$pageLimit` 来自已确定上限。App/MCP 路线按当前依赖追加上述实际参数。最终用户命令必须用本机实际值完整替换这些变量。

运行包应实现所选路线，包含明确的只读范围、超时、有界重试、保守速率/并发、页数/记录上限、来源记录、去重和停止原因。通用运行时提供页数上限、输出检查和检查点，实际分页、应用控制、重试/速率及业务认证判断仍由任务适配器实现。商品 ID 与分类/容器 ID 不混用；一商品多图片及同 URL 多商品关系保留。运行时认证从本地安全渠道取得，不打印原始 Cookie、认证头或密钥。

`app_capture` 适配器在启动、返回及每次点击/滑动前，以有总超时的轮询读取当前 UI，确认目标页面或控件已就绪、可交互且无遮挡；弹窗必须实际出现后再定位处理，固定等待不能代替就绪检查。动作后重新读取 UI，验证对应后置条件；分页还须确认新业务流量及新增 ID，未通过前不继续滑动或推进检查点，超时保留本次部分结果并报告具体状态。

在独立新进程启动生成脚本，写入选定输出文件夹下的一个空测试目录。不得先复制样本 JSON 到那里再称运行成功。至少实际取得非空第一页及第二页新增 ID，对照完整响应抽查名称/ID/URL，检查脚本退出状态、实际数组、报告和检查点一致。默认不下载图片。

### 检查点与失败语义

- 每次已验证业务页后保存已证实记录、来源页/flow、下一页/游标及累计计数；文件写入完整后才推进检查点。
- 页数/范围上限、重复游标、限流、连接/解析失败及认证失效分别记录。配置的累计页数上限不能通过多次 `--resume` 绕过。未知结束条件、短页、文件存在或空数组不能被自动当“全部成功”。
- 已确认会话失效返回清楚的正常登录错误，保留本次运行已取得的可恢复数据；没有真实对象不能返回采集成功。`--overwrite` 明确替换上次结果，新的采集失败也不会自动恢复上次文件，因此默认在新空目录验证，续跑用 `--resume`。合法末页空数组只在已验证分页链中表示结束。
- 用同一检查点重启，确认从实际未完成位置续跑，不重复关系、不跳过失败页。若上游会话改变导致游标不兼容，明确要求重新验证/从已确认位置开始。

验收会话失效行为时使用任务目录里的独立测试配置或模拟传输，不注销用户正常会话、不制造账号锁定。确认缺失本地凭据、HTTP 401、已证明业务登录失效码、403 权限/签名错误和非 JSON 解析错误被清楚区分，停止且保留本次运行检查点；403 不自动输出登录失效。受控失败/签名测试标为离线验证，不代替真实成功采集或真实动态签名证明。

**通过：** 独立新进程实得至少一个真实样本和第二页新增 ID，确实写入选定文件夹；报告/检查点与文件一致；续跑及会话失效错误行为清楚且不空成功。

**失败：** 生成/语法成功而采集未过门槛仍为未验证。保留本次运行的实际错误、已验证部分结果和检查点，修复相关适配后重测；不无界重复请求，不改写本次错误或删除本次数据掩盖失败。明确 `--overwrite` 替换以前运行结果的行为按上述约定处理。

## 4. 交付与恢复

**输入：** 已实测运行包、真实样本/实际运行结果、报告、检查点和环境改动记录。

**执行：** 保留不可变 `sample/`，给用户所选文件夹中的运行包和实际结果。商品任务交付 `collect_data.py`、所有必要运行文件、真实 `products.json` 与 `download_images.py`；请求分析/其他数据使用相应数组名。下载器只运行默认预览，不联网、不创建图片目录。报告实际关系行数、唯一 URL 数、新增记录数、已验证路线/范围、停止原因和依赖；签名图片 URL 的有效期未验证就如实标记。

给用户可点击文件链接及由 agent 在本机实际执行过、全部参数已确定的一条运行命令。说明需保持的设备/App/MCP/登录状态和会话失效时的正常登录动作。用户无需写 mapping、补签名或猜解释器路径。若用户明确要求本次继续完整批量，在已过验收的脚本上按授权范围执行并重新校验最终文件；这不是默认交付前置要求。

只恢复本次实际改变的代理/VPN/录制/forward/模拟器设置。应用/MCP 路线继续运行需要保留哪些状态要说明；不能关掉脚本仍依赖的服务后称可直接运行。无法验证恢复项按 [手动操作提示](manual-steps.md) 主动说明当前动作。

本次发现并修复的问题，只有真实修复后的独立复验至少两次通过，才按 [问题反馈流程](feedback-loop.md) 整理并审查脱敏案例、入队，并在用户已授权且实际有 Issues 权限时自动提交。反馈失败保留队列，不影响已完成的主任务；不能把普通登录、未解决故障或离线模拟测试写成已验证解决方式。需要通用 Skill 改动时保留可复用部分，按单独授权的 PR 范围处理，不把任务适配或业务资料写回仓库。

**通过：** 交付实际存在的完整运行包和非空真实结果，下载预览、来源抽查、独立运行/续跑/失败检查均有证据；命令及依赖清楚，恢复状态有记录。

**失败：** 缺模块/路径/有效会话或改变了最终文件，先修复并重测受影响项。只报告已完成验证，不将离线测试或别的 App 的成功推广为本次成功。
