# 排错与实测经验

从已经得到的证据开始，一次改一个必要条件；每次改动后用新的目标请求验证。以下经验用于判断，不是所有 App 的安装前提。

## MCP 不能连接

确认 ProxyPin 正在运行、MCP 开关开启、当前面板 URL。桌面与手机可能是不同实例；手机端口重启可能改变，令牌重置后旧配置失效。手机局域网路径检查同网、隔离策略和真实连通；桌面本机路径不用手机 Wi-Fi。保持默认脱敏，token 只存于安全环境/隐藏输入，错误信息不回显它。当前工具名或参数不匹配时重新 `tools/list`；无 MCP 才使用 HAR 备用路径。

## 录制中但目标请求没有进来

`recording=true` 只说明 ProxyPin 录制状态，不能证明手机 VPN 授权或目标 App 使用系统代理。查本次路径：VPN 是否已批准，Wi-Fi 代理是否指向实际电脑地址，过滤是否排除了真实域名，当前操作是否由缓存满足。先触发一个新的普通网页请求验证路由，再做用户目标动作；分别记下证据。不要把手机浏览器成功当作目标 App 已成功。

Android 全局 HTTP 代理能影响一部分 Java/系统流量，但部分 Flutter/Dart 流量可能不采用它。遇这种现象优先验证 ProxyPin VPN 路径；不立即推断接口没有请求或必须改 APK。应用白名单不是必需步骤；只有确需减少杂流量并且包名已核实才使用。厂商“已安装应用列表”权限问题只在实际出现时处理。

电脑和设备时钟可能不同步。优先保存操作前的目标 flow ID 集合，用新 ID、完整请求中的真实分页参数及新增业务 ID 判断新流量。先比较两端实际时间再使用 `since_ms`；不能因为电脑时间筛选返回空就判断没有请求。流列表有条数上限时按当前工具 schema 用已观察主机/路径过滤并分页，不能让大量图片流挤掉业务 JSON 后误判。

App 启动、刷新和预加载可能产生多个相同页的请求。不能直接要求每个动作只能出现一个 flow，也不能随便选一个响应。逐条检查实际请求中的页/游标、业务成功及完整商品关系；同页重复请求的身份、名称和 URL 一致时可保留一条已完成 flow 作为来源，并记录重复。正文不一致或来源无法区分时停止并重新观察，不把多份第一页算成第二页。

首次安装可能停在隐私协议、首次引导或活动弹窗，先检查当前屏幕并完成普通初始化，再触发目标动作。ProxyPin 悬浮窗遮挡按钮或使 UI dump 只含悬浮窗时，在当前偏好设置中核实并关闭 Window Mode，再检查目标页面；不要靠撤销运行中悬浮窗权限或猜坐标解决。UI dump 超时不等于 App 无页面，可用本次截图确认普通页面；含 MCP 令牌或认证的页面不输出截图。坐标动作必须验证当前屏幕尺寸、前台包和动作后新业务响应。

## CONNECT 或 TLS 握手失败，正文不可读

检查当前 CA 是否安装/信任、抓包链路是否经过当前实例、HTTPS 拦截开关及域名范围。`enable_ssl_proxying(domain=...)` 在部分版本仅改变黑名单，不自动创建 SSL 白名单；调用后读取范围，按当前 schema 验证目标确实被拦截。不要替换用户整份白名单或开启所有域名来掩盖范围错误。

证书 subject hash 相同不证明是同一张证书，核对实际证书指纹。重新生成 CA 后旧证书可能不适用；不要用上一台电脑的 CA 或固定“ProxyPin 默认 CA 一样”的假设。

Android 用户 CA 已安装不意味着所有 App 信任它；部分 Flutter/Dart 版本的信任实现与 Android 用户 CA / network security config 不同。TLS 失败也不能单凭日志认定证书固定。普通连接、VPN、范围、CA 都验证后，再说明现有限制与可选诊断；不默认给真机或用户已有 AVD 安排 root、改包或系统 CA 变更。

采用已授权的任务专用模拟器路线、且所需正文确因证书信任不可读时，按 [隔离模拟器路线](emulator.md) 验证 root/remount 能力、实际信任目录及本次 CA 指纹，再完成必要的系统 CA 设置。已有授权范围内不为每个普通准备步骤重复询问；涉及范围外设备或宿主要求本人确认时说明具体影响并取得相应授权。Android 14+ APEX 与 Flutter/Dart 可能采用不同目录，不能盲写固定路径。重启后重新验证，系统临时副本不保证持久。

正确路由和证书状态验证后仍失败时，记录证据并说明是否疑似 pinning、自定义信任或设备完整性限制。系统 CA 不保证解决这些限制；不默认禁用 TLS 验证、关闭 SELinux、重打包或注入。可转真机、用户拥有的调试构建或官方接口/导出路线，分别验证其实际能力。

iOS 手动安装证书描述文件后还需完全信任；两轮主动指导见手动步骤。仅电脑证书已信任不足以说明手机可解密。

## 响应看起来空、乱码或不完整

- HTTP 200 可能携带业务错误、版本提示、登录失效或参数缺失；读实际业务字段，不统一假定 `code=0` 或 `code=200`。
- 不假定正文是 Base64。只有观察到对应包装并且解码可验证为 UTF-8 JSON 时才解码；压缩、二进制和应用加密另行判断。
- 某些实测版本 `send_request` 预览限制为 8192 字节。用相应 flow 的完整 body 分页；不能对截断 Base64 解码或依靠残缺列表统计。
- 捕获范围、客户端参数和分页状态确认后，才能将空页用作停止条件。记录缺页、失败分类与登录/限流问题，不编造全量成功。
- agent 请求和实际 App 请求可能同时出现在流量列表中。记录 agent 发出的时间与 flow ID，来源不能只依据 URI、时间或 HTTP 状态。

## 商品和图片不对应

由实际业务字段建立商品 ID、名称与 URL 关系；商品 ID 和集合/容器 ID 分开，不从图片文件名猜 ID。预览只有图片而没有商品名时输出待关联记录；不能用一个集合名冒充每件商品名。相同 URL 可以对应多个商品，去重时保留全部关系。缩略图转原图只在参数语义已确认时做，默认保留原始 URL。

签名链接可能过期；含会话凭据的链接不能静默输出到共享文件。根据实际权限与用户目标决定留在受控环境、报告待处理项或寻找无需会话的公开资源 URL，不把被脱敏的坏链接写成可下载商品图片。

## 更新弹窗阻挡操作

优先通过官方更新恢复正常抓取。用户明确要求调试弹窗时，先捕获并确认实际版本查询及影响；如确需可逆响应规则，精确限定已证实的版本接口，保留原规则并验证撤销。不要预置“屏蔽所有更新请求”，不要把其他任务的旧规则带到新 App。

这些判断来自不同抓包路径的操作经验；不包含任何实例 App 的硬编码接口。官方行为参考：[ProxyPin](https://github.com/wanghongenpin/proxypin)、[MCP 文档](https://github.com/wanghongenpin/proxypin/wiki/MCP%E6%9C%8D%E5%8A%A1)、[Apple 证书信任](https://support.apple.com/en-us/102390)。
