# 全链路执行规程

这是实际执行入口，适用于 Codex 或其他具备相应工具的智能体。先完成入口检查，再按阶段 ID 执行；每阶段看“输入、执行、通过、失败”四项。下面是 agent 的操作规程，不是发给用户的配置清单。

## 入口检查：先确认能执行

1. 定位本次 Skill 根目录，确认 `scripts/`、`references/` 可读。只拿到一段 SKILL.md 而没有资源时，先从用户授权来源准备完整目录；不能假装附带脚本已在电脑上。
2. 实际调用现有工具验证：命令在哪台机器运行、可读写目录在哪、是否能联网、是否能读取当前设备/浏览器、是否已有 ProxyPin MCP。不要凭工具名称推断具备权限。
3. 按下表选执行方式并记录能力证据。`127.0.0.1` 属于命令执行所在机器；云端沙箱里的本地端口不是用户电脑的 ProxyPin。先证明命令/设备与目标在同一可达环境。

| 已有能力 | 现在怎么做 | 不应承诺什么 |
|---|---|---|
| 本机命令、文件、联网；可用 ADB/UI 或可准备模拟器 | 执行本规程与脚本，自动配置并抓样本 | 未验收前不说已经抓到商品 |
| 原生 ProxyPin MCP；没有本机命令 | 用原生工具读真实 flow；按工具 schema 执行相同检查。可控 UI 才代操作 | 不能说在用户电脑安装了 Python/ADB |
| 可读用户提供的真实 HAR/抓包文件 | 使用导入分支，不再要求配置手机 | 文件导入不算本次实时抓包 |
| 只有聊天；无本机工具、MCP 或真实文件 | 明确缺少执行入口，提示接入可执行本机命令/文件的宿主或提供可读取抓包 | 不能靠 Skill 文字自行接管手机，也不能生成假数据 |

有命令但无 UI 控制时，安装和 MCP 分析仍可自动完成；仅目标页面点击交给用户。请求用户动作前先确认没有可用 ADB/其他控制路径。能力不足不是“让用户从头自己装所有东西”。

## 状态与工作目录

建立独立任务目录，放在 Skill/仓库之外。建议分为 `evidence/`（脱敏状态/观测）、`private/`（UI dump/正文/临时 CA）、`sample/`（不可变样本）、`final/`（最终交付）、`tools/`。只在需要时建立相应子目录；**没有下载请求不创建图片目录**。

Python 可用后按 [命令配方](command-recipes.md#会话状态) 初始化会话。每轮先运行 `status`，只执行它给出的 `current_step`。完成真实观察后保存原始工具结果或有引用的观测记录，再以 `agent-observed` 登记；不是先写“成功”再找证据。证据至少注明实际动作/命令、检查项和来源文件/flow ID，不保存密码或 token。

`file-validated` 只说明本地文件检查，`user-reported` 只说明用户报告；它们不自动推进。状态助手的 `business_success:not_auto_verified` 是固定说明，agent 仍须判断实际业务证据。已有状态用 `status` 接续，不再次 `init` 覆盖；原证据改变会要求重新验证相关阶段。

无命令/文件工具时用同样阶段表记录在当前任务，不能声称运行了状态脚本。每次接续重新检查设备在线、MCP 面板/鉴权与 VPN；以前的证据不保证连接此刻仍有效。

## target

**输入：** 用户目标和现有上下文。

**执行：** 确定具体 App/网站、目标数据/动作、设备要求、样本或批量、是否下载、已有捕获。只问缺项。商品图片默认交付名字与 URL 的数组及下载脚本，不下载。范围“全部”先记为尽量遍历可访问目录，不能承诺未知后端全量。

**通过：** 目标/范围记录可读取；明确用户是否要求真机及现有登录会话。初始化选择 `products/requests/data`、适当 route；批量加 `--batch`，必须真机加 `--require-physical`。

**失败：** 目标名称/来源无法确认时只问必要信息，继续准备不依赖目标的工具。不能拿同名 APK、示例域名或其他 App 替代。

## host_tools

**输入：** 入口能力记录、选定运行环境。

**执行：** 按 [初始化](bootstrap.md) 准备实际缺失的宿主 Python 3.10+、ADB 与所需安装包。记录绝对路径，采用 [命令配方](command-recipes.md#解释器与初始化) 运行脚本 `--help`；只验证 `python --version` 或标准库不够。Windows helper 的 `status/pending` 要检查，进程退出 0 不代表它全部成功。工具目录放任务目录，不接受默认写入 Skill 的缓存位置。此阶段只验宿主工具，不要求尚未创建的设备在线；移动 ProxyPin 与目标 App 在 route_device 验收后安装，桌面路线按需准备可执行程序。

**通过：** 命令确在选定宿主执行，本次实际解释器能运行所需脚本，所需 ADB/宿主程序可执行或安装包已准备。设备是否可达由下一阶段验证，不以设备缺失阻塞宿主验收。MCP 原生分支没有 Python时，不把 Python作为读流量的前提。

**失败：** 安装失败查具体缺项。软件包来自官方当前来源，URL/架构/校验来源确定后再装；没有联网或写权限记录待处理。只有实际本人密码/工具不能操作的步骤交给用户，不修改全局安全策略。

## route_device

**输入：** 目标/真机要求、设备列表或模拟器配置。

**执行：** 已有可用路径继续用。需要真机会话/硬件/完整性或用户指定真机时选真机；否则新建 Android 自动化环境先验证专用模拟器，按 [模拟器准备配方](command-recipes.md#模拟器准备) 执行 `check → discover → 选择实测镜像/profile → prepare → start → verify`。镜像/profile 尚未知可为 null；discover 先准备缺失的管理工具再返回实际候选，不创建 AVD。真机查看 `adb devices -l`，所有后续命令指定唯一 serial；模拟器用 `emu avd name` 验证归属。iPhone 仅用实际支持 iOS 的工具。

**通过：** 目标设备正确、在线，可读取当前屏幕或已明确 UI 由谁操作。进程启动不代表开机完成；启动完成不代表联网或 App 兼容。

**失败：** `unauthorized` 且没有替代控制工具时才让用户解锁并确认授权；模拟器不发真实手机 USB 指导。模拟器确实不可用且尚未抓业务 flow 时可用 `set-route` 有证据地转真机；明确要求真机时不自动转模拟器。已经捕获后更换路线须建立独立会话，避免混淆来源。

## app_baseline

**输入：** 正确设备、已核实官方 APK/商店来源或网站。

**执行：** 在已验收的 serial 上安装/复用移动 ProxyPin 与目标 App，核对包名、版本、ABI/minSdk和实际前台页面。由 agent 在未拦截状态进入目标列表与至少一件详情；网站访问目标页面。保存界面/联网基线。有现有抓包或其他用户会话时不随意停止它们，只改变本任务实例。

**通过：** App 身份正确，目标页面可用。不能仅用 `adb install` 的 Success 代替业务检查。

**失败：** 登录本人验证主动提示；更新弹窗优先官方更新。Google 服务、ABI、模拟器检测或硬件不兼容按证据回退。不能默认卸载、清数据、降级或改包。正常不拦截都打不开时，先修 App/网络而非证书。

## mcp

**输入：** 当前 ProxyPin 实例与当前 MCP 面板。

**执行：** agent 打开面板、启用 MCP，读取真实 URL；连接一次 `initialize/tools/list` 并将 schema 保存在证据目录。移动版即使经 loopback ADB forward 也必须 Bearer：按 [移动鉴权配方](command-recipes.md#移动鉴权) 从本次 UI dump 本地交接，或在本机交互终端隐藏输入。没有原生 MCP 时使用客户端，不先修改助手的全局 MCP 设置。

**通过：** 当前实例 initialize、tools/list 和状态读取成功；确认所需 `list_flows/get_flow_detail/get_flow_body` 存在及实际参数。不要只测 TCP 端口。

**失败：** 401/403 重新核对本次移动 token/实例；连接拒绝核对面板、监听和路由；参数错误读 schema。相同未解决原因不盲目重试。不能让用户把 token 发聊天，不能用 `--no-token` 绕过移动鉴权；无 MCP 才转真实 HAR 导入。

## capture_route

**输入：** MCP 状态、录制/SSL/过滤与网络原状态。

**执行：** 移动版由 agent 在 UI 开始抓包并确认 VPN，读可用 VPN 状态；电脑软件确认采用本机代理。记录原状态再改。本任务新普通请求可用于先验证链路，再验证目标 App；不把电脑浏览器的成功当目标 App成功。范围先观察再缩小，不猜域名白名单。

**通过：** 当前路径、录制与目标应用路由分别有证据。`recording=true` 不代表 VPN 接管；MCP 本身的 HTTP 请求不是商品业务请求。

**失败：** 无流量查 VPN、目标包过滤、代理、缓存；全局 HTTP 代理对目标 App 无效时验证移动 VPN。VPN 冲突先记录原状态、限定处理，不静默关闭别的用户工具。证书问题留到 required_body 分支，不在无请求时反复装 CA。

## real_flow

**输入：** 已验证路由与可操作目标 UI。

**执行：** 先保存 flow ID 列表或 `since_ms` 基线，再读当前屏幕并操作一个目标动作。刷新列表/进入详情后查询新流，记录动作、时间、真实 ID、URL、方法和来源。未知主机先看新流；必要时用响应中的已知商品名搜索。工具无法点手机时才给用户具体当前动作，完成后检查新流。

**通过：** 至少一条新请求确与目标动作对应。它不是旧历史、广告、头像、MCP请求或 agent重放。历史文件分支通过实际请求及采集来源建立关联，不声称实时触发。

**失败：** 先确认页面确变/缓存刷新，再回 capture_route检查。最多作两轮有实际改动的样本触发；没有新证据就记录具体缺项，不无限滑动。没有业务证据不创建商品结果。

## required_body

**输入：** 真实 flow ID、输出所需字段。

**执行：** 按 [正文配方](command-recipes.md#工具调用与完整正文) 读取详情（保持脱敏）及完整响应；客户端 `--body-flow-id/--body-output` 自动分页，原文只存私有目录。核对 HTTP 状态和实际业务状态。仅 URL元信息足够的请求分析可记录“无需正文”的证据；商品名与图片关系通常需关联 JSON。

**通过：** 正文完整可解析、业务状态符合观察；二进制只读元信息不算取得图片字节。确认 Base64包装后才按实际字段解码。

**失败：** available=false/binary：查详情和关联 JSON，不能截取预览强行解析。TLS失败先核对路由、SSL范围、当前CA指纹；真机用户CA不被接受不等于可擅自root。已授权专用AVD需要系统CA时按 [模拟器证书分支](emulator.md#必要的系统-ca) 验证目录/root/remount能力；APEX只读或正确CA仍失败就报告限制，不能关闭TLS/SELinux强行通过。

## mapping

**输入：** 一个完整、真实、业务成功的响应。

**执行：** 商品任务确定列表路径、每个对象的名字/URL/ID路径、精确 host/path；再生成本任务 `profile.json`。每个字段都有实际样本位置，业务状态存在时放入 `decode.success`（普通JSON及Base64均支持）。按 [映射配方](command-recipes.md#字段映射与样本导出) 只导出一个已证实 flow。

**通过：** `report.mapping.matched_flows>0`、真实对象存在、名称和URL成对。无名图片放待关联文件，不能从文件名造名字。请求分析跳过此阶段；特殊跨层关联不硬塞简易mapping，先说明当前脚本能力，再用已验证适配方式。

**失败：** 规则没命中先查host/path；命中但字段缺失查记录路径及相对字段；业务错误查session/参数。合法空数组表示这次业务没有对象，不能拿它通过商品样本阶段或声称抓到了商品。

## sample_output

**输入：** 样本 JSON、导出 report/errors、完整源正文。

**执行：** 保留 `sample/` 不覆盖。使用 `validate-output` 校验数组并在商品任务复制下载器、运行默认预览；抽查至少一条名称、ID和每张图URL对照完整源对象。签名资源 URL 仅确认是图片签名时显式放行，并保留 `expiry_status:not_checked`；账号凭据不放行。

**通过：** 非空真实数组、导出错误已判断、结构检查及来源抽查通过。`validate-output`不自动放行：用真实抽查记录pass本阶段。用户只验证可行性时这份样本可作为最终结果。

**失败：** 空数组/保留示例域名/坏URL/缺名字/凭据混入修对应字段或来源，不直接改JSON掩盖源数据。没有下载请求不传 `--download`，预览不联网、不创建图片目录。

## batch

**输入：** 已通过样本与用户明确批量目标。

**执行：** 只扩大已观察的分类/列表/详情。优先继续UI遍历；API重放必须已确认只读及真实分页参数。记录每页来源ID、记录数、下一游标、失败及停止原因，agent重放单独标记。建议首批10页、单并发验证，再按用户范围扩展；上限到达报告覆盖而非声称全部。

**通过：** 停于已确认末页/空业务页/重复游标/限流/实际范围上限，生成 `final/` 新文件，不覆盖样本。重新 validate-output最终数组并抽查新增记录；只有每个已见目录都验证结束，才称“已遍历已发现目录”。

**失败：** 登录失效/限流/重复错误停止扩展，保留已证实记录和失败范围。仅返回少于请求页大小不自动当末页；导出器会按实际行数推进flow列表，业务分页仍按响应证据判断。用户没要批量时状态助手自动跳过。

## deliver

**输入：** 最终JSON、脚本、校验与覆盖报告。

**执行：** 在本阶段可再次 validate-output最终文件；批量必须有最终校验，不能只验样本。检查下载器在JSON同目录且预览通过。给可点击文件链接、关系行数与唯一URL数、覆盖/缺口、URL有效期未验证项；用户需要自行下载时给已验证解释器绝对路径的一条命令，不能假设`python`已在PATH。

**通过：** 用户能找到实际文件，最终内容对应来源和当前计数。没有真实商品成果只交付排错状态/可用请求摘要，不放示例数组充数。

**失败：** 找不到文件、内容变更或预览失败先修交付，不停止MCP清空实时证据。原始正文、UI dump、认证头和token不作为通用交付文件。

## restore

成功路线按当前阶段登记 restore。若任务在较早阶段无法继续，先把当前阶段标为 pending，然后仍恢复本次已经改变的配置；用 [失败恢复登记](command-recipes.md#失败恢复登记) 单独记录实际观察。恢复不要求假装业务成功，也不推进尚未完成的阶段；status 继续显示原待处理阶段及独立恢复状态。后续重试须重新检查运行状态，不能用已停止实例的旧证据继续抓包。

**输入：** 本任务改变的代理/VPN/SSL/过滤/forward/AVD归属记录。

**执行：** 先导出，再分别停止/恢复本任务录制、VPN、MCP与规则；删除具体forward。模拟器用prepare helper的stop核对实例，不删除共享SDK或其他AVD。临时正文/截图/缓存按用户清理范围处理；不删正式Skill或交付结果，除非用户也要求。

**通过：** 实际检查恢复状态。保留模拟器时下次重新确认CA/VPN/MCP；writable-system CA不保证重启保存。用户介入项按 [提示](manual-steps.md)主动说明并保持待验证。

**失败：** 无UI/权限无法恢复就明确哪项仍生效，给当前具体动作；不能用关闭全局代理、kill-server、清账号或删除全部AVD替代恢复。结果已交付但恢复未验证要如实分开报告。

## 导入已有捕获

确认本地真实 HAR/会话属于用户目标且包含所需请求；记录来源与文件SHA256。用`existing-capture`初始化，指定`--capture-file`、`--capture-origin`和已审查适用性；状态助手跳过host_tools至capture_route，仍验证real_flow、正文、映射和输出。

`export_capture.py`处理已有MCP flow，**没有`--har`参数**。只有HAR文件时由可用文件分析工具读取`log.entries`，按对应请求/响应与编码解析；没有可用分析能力就说明缺项，不能把HAR路径塞给不支持的脚本。由实际字段提取并执行同一输出检查；无现场改动的restore记录为“本次未改变设备配置”。
