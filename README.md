# ProxyPin 抓包助手 Skill

面向不会代码的用户：由具备工具的智能体分析少量真实 ProxyPin 流量，选择经验证的采集方法，生成并实测独立运行脚本。脚本负责后续有界批量采集，将 JSON 保存到用户选定文件夹。仓库保存通用流程与工具，不包含某个 App 的接口、账号、签名密钥或商品数据。

## 默认执行方式

加载 [SKILL.md](SKILL.md)，每次先同步已配置仓库最新的问题与解决方式，再从 [脚本生成与验收](references/script-generation.md) 按四阶段推进：

1. 确定目标、范围和输出文件夹，实测执行宿主、解释器、设备/浏览器及 MCP 能力。
2. 取得真实非空样本和第二页/下一游标新增 ID，分析映射、业务状态、认证、签名及分页，选择有证据的路线。
3. 生成任务运行包，在独立新进程实际采集并保存；检查报告、会话失效错误和续跑检查点。
4. 交付实际文件及本机已运行命令，说明依赖、计数、覆盖和停止原因，恢复本次改动。

默认不要求智能体手动遍历完整批量后才交脚本。缺少工具、设备、业务基线、MCP/路由或完整正文时，才进入 [准备与抓包支持规程](references/runbook.md)；它保留 13 阶段的输入、通过条件和失败分支。已有可用环境复用，已有真实捕获走导入分支。`capture_session.py` 管理该支持流程，不替代生成脚本的独立运行验收。

直接 API 必须通过新鲜真实请求两页重放、第二页新增 ID 和必要的动态签名生成器实测。算法未证明时保留 App/浏览器产生新签名请求，通过 ProxyPin MCP 收集，再由运行脚本提取和保存；该路线仍需可用设备/应用/MCP。复制旧签名成功一次不能证明可批量采集。

出现登录页面、目标业务 HTTP 401 或已确认业务登录失效码时，停止采集、保留本次运行部分结果与检查点，先主动提醒用户在原 App/网站正常登录。HTTP 403 也停止并检查原应用会话，但可能是权限/签名问题，不能自动认成登录失效；HTTP 200 非 JSON 不能自动认成登录页。本人验证在用户本机完成，智能体验证新业务成功响应后再续跑。ProxyPin MCP 的服务鉴权失败另行核对当前令牌和实例。

## 新电脑与其他智能体使用

需要完整仓库目录，包括 `scripts/`、`assets/` 和 `references/`；只复制 SKILL.md 文字不能得到附带工具。公开仓库可匿名读取；目标仓库为私有时需要当前 GitHub 账号具有读取权限。提交反馈另需身份和 Issues API 的实际提交权限，不能由克隆成功或 Git 推送权限推断。新环境自行发现路径、设备、MCP 地址和令牌，不迁移旧电脑的账号或配置。

Codex 可以使用 `$skill-installer` 从仓库根目录安装：

```text
请从 https://github.com/2912826201/proxypin-capture-assistant 安装
proxypin-capture-assistant Skill，Skill 位于仓库根目录。
```

其他宿主按其技能加载方式读取完整目录。智能体至少需要实际可用的本机命令/文件工具、原生 ProxyPin MCP 或可读取的真实抓包文件。**普通聊天不会因为加载 Skill 自动得到电脑/手机控制权。** 云沙箱的 `127.0.0.1` 也不是用户电脑的 ProxyPin；执行前实测可达性。

使用时说明目标即可，例如：

```text
请用 proxypin-capture-assistant 从零准备工具，分析我指定 App 的少量
真实请求，生成并测试采集商品名称和图片 URL 的脚本，保存到我选定
的文件夹。尽量由你操作，只在本人登录等无法代办时主动提醒我。
这次交付样本 JSON 和批量下载脚本，不下载图片。
```

## 问题反馈与持续改进

每次运行都尝试从配置的 GitHub Issues 及评论同步最新经验，默认来源为本仓库，并检查持久队列中的待提交案例。空白电脑缺少同步工具时复用主任务必要的最小准备，或使用已有只读连接器；网络、权限或工具不可用均不阻塞抓包，有旧缓存就保留其时间标记。经验只作排查线索，仍须在当前设备、App 和环境验证。

用户可以一次授权“解决后自动反馈”。以后遇到的问题真实修复并至少重复验证两次后，智能体审查脱敏摘要，通过 Issues 提交问题、环境类别、原因、解决步骤、验证和适用边界；同类问题更新原 Issue，重复案例不重复发帖。不开启自动反馈时只保存本地待提交材料。授权与缓存保存在 Skill 外，不随仓库分发，也不保存 GitHub token。

读取、创建 Issue、推送代码是不同能力。公开仓库通常允许有相应权限的登录用户提交 Issue；私有仓库先需要访问权。没有提交权限时保留本地队列并说明所缺权限；只有用户另行指定可访问的反馈仓库后才切换，不能自动发到公共仓库或创建 fork。自动提交 PR 是另一项可选授权，改进经过验证后进入 PR，不由每个客户端自动覆盖或合并主分支。

流程、命令与反馈字段见 [问题与解决方式反馈](references/feedback-loop.md)。只上传经过审查的通用经验，不上传 HAR、请求正文、账号、token、Cookie、设备序列号、IP、路径、业务 URL 或商品数据；自动扫描不能代替内容审查。

## 按需准备与设备操作

- Windows 初始化助手探测/准备缺少的 Python、ADB、官方 ProxyPin 和核实过的目标 APK；不要求预先有 Python。工具、任务适配与采集数据保存在 Skill 之外。
- 新建 Android 自动化环境先检查任务专用模拟器兼容性；用户指定真机、需要现有会话/硬件/完整性时保留真机。只操作本任务已验证设备/实例。
- 安装、配置、UI 和验证能由工具完成时由智能体代办。只有 BIOS/重启、本人登录或实际无法代办的授权才提示当前必要动作；用户无需研究命令和 mapping。
- 移动 MCP 仍需 Bearer，ADB forward 不取消认证；令牌从当前 UI 本地交接或本机隐藏输入，不发到聊天。
- 系统 CA 只在必要的隔离模拟器分支处理，不保证解决登录、pinning 或设备完整性；重启后重新检查 CA、VPN、MCP 与业务请求。

具体见 [初始化](references/bootstrap.md)、[模拟器](references/emulator.md)、[设备接管](references/device-control.md)、[命令配方](references/command-recipes.md) 和 [必要手动动作](references/manual-steps.md)。所有 Python 工具使用 Python 3.10+ 标准库。

## 交付结果

| 任务 | 默认交付 |
|---|---|
| 商品采集脚本 | 实测 `collect_data.py` 及全部运行文件、真实样本与运行产生的 `products.json`、报告/错误/检查点、`download_images.py` |
| 已捕获网络请求分析 | `requests.json` 数组和来源/覆盖说明 |
| 其他结构化数据 | 根据真实字段编写并实测的任务脚本与 `data.json`；当前商品工厂不自动支持任意格式 |

商品 JSON 每行关联真实名称与图片 URL，保留真实 ID/来源。同一 URL 对应多个商品时保留关系。至少验证一个实际样本、第二页新增 ID、独立新进程写入选定文件夹、会话失效明确停止和检查点续跑。默认使用新空目录；`--resume` 续跑受配置累计页数上限约束，`--overwrite` 明确替换以前结果且不提供旧文件备份。只验语法、工厂退出 0、MCP 连通、HTTP 200、合法空数组或已复制的 JSON 均不算采集成功。

默认只采集 URL。下载器默认预览，不联网、不创建图片目录；只有明确请求下载时才用 `--download`。用户命令由智能体用实测解释器与真实绝对路径填写并执行，用户不需要改代码或猜 `python` 是否在 PATH。签名图片 URL 未测试有效期时明确标记。细节见 [输出约定](references/output-contract.md)。

## 配套工具与真实边界

| 工具 | 作用 |
|---|---|
| `generate_collector.py` | 校验本地任务适配、配置和 agent 记录的真实证据报告，生成商品采集运行包 |
| `assets/collector_runtime.py` | 生成的 `collect_data.py` 来源；有界运行、输出检查、检查点、部分失败和续跑 |
| `bootstrap_windows.ps1` | 宿主探测与按需初始化、安装移动 APK |
| `prepare_emulator.py` | 发现工具/镜像，准备和验证任务专用 AVD，精确停止 |
| `capture_session.py` | 准备/抓包阶段与证据状态，样本/最终文件校验，失败恢复记录 |
| `mobile_mcp.py` | 当前移动 UI 令牌的本地交接 |
| `proxypin_mcp.py` | MCP schema 发现、参数文件调用、完整正文分页保存 |
| `export_capture.py` | 提取已有真实 flow 及映射商品；报告错误与命中情况 |
| `download_images.py` | 商品图片 URL 默认预览及显式批量下载 |
| `feedback_report.py` | 外置授权设置、Issues/评论同步、脱敏案例入队及有权限时去重提交 |

工厂不会自行发现 App 接口、推导签名或登录；智能体必须为本任务编写并审查适配器，完成真实验证。运行包中的 `agent_verified` 仅记录 agent 的观察断言及 hash；运行报告同样注明适配器断言未被独立自动验证。工厂不联网，运行时不自动证明业务成功或未知后端全量，也不含目标 App 的默认适配。

`export_capture.py` 只读取已捕获的 MCP flow，不支持 `--har`；HAR 使用支持规程的文件分析分支。App/MCP 采集路线必须实际实现可用控制和捕获，若还需用户翻页要在交付中说明。请求重放仅限已确认只读查询，不用下单/支付或未知写操作探测。确切工厂配置、适配器与命令接口见 [脚本生成参考](references/script-generation.md)。

## 验证范围

`tests/` 的离线测试检查状态、模拟器、移动鉴权、MCP、导出管线及采集运行包的行为，适用于发现空输出、业务失败、证据缺失、分页/检查点和文件变化等问题。离线测试不安装软件、不启动设备、不抓真实业务流量，不能证明某个 App 的接口、动态签名或完整批量已可用。

历史上特定 Android 环境曾取得真实 HTTPS 流量，这不保证其他 App、宿主或会话成功。每个任务仍需用本次样本、两页新增记录和独立运行结果验收；未通过的路线明确报告当前边界。用户指定“全部”时只报告实际覆盖与缺口，不承诺通用成功率或未知后端全量。

本 Skill 与 [ProxyPin 项目](https://github.com/wanghongenpin/proxypin) 独立；仓库仅保存通用工作流、运行模板、辅助代码和测试。
